# 1.3.1 MCU Firmware Decompilation & CAN Architecture Reference

Technical reference and decompilation documentation for the STM32F105 companion MCU firmware (`can_app.bin`) used on the Limcet Box P305/P306 CarPlay / Android Auto head unit platform.

> **⚠️ Before flashing anything built with `tools/mcu_builder/` to a real vehicle:**
> - The `toyota_prado_150` preset (§6) patches **two** CAN IDs. Only the SWC one
>   (Mode 1 Entry 7, `0x105 -> 0x3C4`) has any real basis in this project's own
>   research. The second (Mode 1 Entry 4, the reverse/parking-sensor handler,
>   `0x185 -> 0x025`) is **unverified** — `docs/1.2_CANBUS.md` lists `0x025`/`0x026`
>   as *typical Prado SWC* candidate IDs, not reverse-gear/parking-sensor IDs, and
>   explicitly warns to confirm CAN IDs via a live capture on your specific vehicle
>   before programming any MCU firmware. If `0x025` is actually SWC traffic on this
>   vehicle, steering-wheel button presses could spuriously trigger the
>   reverse-camera/parking-sensor handler while driving.
> - No checksum/CRC covering the whole flash image has been found — only the
>   runtime UART wire-protocol has one (§5). Whether the resident bootloader
>   validates a flashed image beyond YMODEM's own per-block transport CRC is
>   **not confirmed**.
> - Keep a known-good copy of the stock `can_app.bin` before flashing a patched
>   image to real hardware.

---

## 1. Firmware Overview & Memory Architecture

- **Target MCU**: STMicroelectronics STM32F105RBT6 (ARM Cortex-M3, Connectivity Line).
- **Core Parameters**: 128 KB Flash memory (`0x08000000 - 0x08020000`), 64 KB SRAM (`0x20000000 - 0x20010000`).
- **Binary Image**: `hardware/MCU/can_app.bin` (31,996 bytes).
- **Base / Link Address**: `0x08004000`.
- **Initial Stack Pointer (SP)**: `0x20002DC0`.
- **Reset Vector**: `0x08004239` (Thumb execution starts at `0x08004238`).

### 1.1 Memory Partitioning
```
0x08000000  +---------------------------------------+
            |  Resident Bootloader (16 KB)          |
            |  - YMODEM receiver over USART2/ttyHS0 |
            |  - Flash erase & program routines     |
0x08004000  +---------------------------------------+
            |  Application Binary (can_app.bin)     |
            |  - Vector Table (0x08004000)          |
            |  - Startup & SystemInit               |
            |  - bxCAN Driver & Filter Engines      |
            |  - CAN Mode Dispatch Tables           |
            |  - UART Protocol Parser & Dispatcher  |
0x0800BD00  +---------------------------------------+
            |  Unallocated Flash (to 0x08020000)    |
0x08020000  +---------------------------------------+
```

## 3. CAN Bus Subsystem & Frame Processing

### 3.1 Reception & Ring Buffer Flow
1. **CAN1_RX0 ISR (`0x08007064`)**:
   - Reads hardware FIFO0 via `CAN_Receive()` into a 15-slot circular software ring buffer located in SRAM at `0x200002BC`.
   - Each slot is 20 bytes (`CanRxMsg` structure):
     - `+0x00`: `StdId` (uint32_t)
     - `+0x04`: `ExtId` (uint32_t)
     - `+0x08`: `IDE` (uint8_t: 0 = Standard 11-bit, 4 = Extended 29-bit)
     - `+0x09`: `RTR` (uint8_t)
     - `+0x0A`: `DLC` (uint8_t: Data Length Code)
     - `+0x0B..0x12`: `Data[0..7]` (uint8_t array)
     - `+0x13`: `FMI` (uint8_t)
   - Ring write index (`head`) is maintained at SRAM offset `0x200002BC + 0x12C`.
   - Ring read index (`tail`) is maintained at SRAM offset `0x200002BC + 0x12D`.

2. **CAN Message Dispatcher (`0x08007F04`)**:
   - Drains the circular buffer: pops the next frame when `head != tail`.
   - Determines ID (`StdId` or `ExtId` based on `IDE`).
   - Reads `mode` byte from SRAM `0x200002BC + 0x36`.
   - Iterates through the corresponding Mode Table and calls the matching handler function.
   - Forwards/relays the frame through `CAN_Transmit()` (`0x08004CD2`) onto CAN1.

## 5. UART Protocol to ARK1680 SoC (`/dev/ttyHS0`)

The MCU communicates bidirectionally with the ARK1680 SoC over USART2 configured at **38400 baud, 8N1**.

### Wire Framing Format
```
[0x2E] [CMD] [LEN] [PAYLOAD (LEN bytes)...] [CHECKSUM]
```
- Header: `0x2E`
- Command byte: Protocol command ID
- Length: Number of payload bytes
- Checksum: One's complement of byte sum (`~sum(CMD + LEN + PAYLOAD) & 0xFF`)

### Inbound UART Command Dispatch Table (`0x0800B9E4`)

The MCU receives commands from the Linux SoC over UART2 (`/dev/ttyHS0` at 38,400 baud, 8N1).

| Cmd | Handler Address | Payload | Role / Behavior |
|:---:|:---:|:---:|---|
| **`0x81`** | `0x080088B5` | `[0x01]` | **Initialization Handshake / Keepalive**: Resets internal watchdog/state slots (12, 1, 8, 10). |
| **`0x82`** | `0x08008BD5` | `[appMode]` | **Application Mode Notification**: `1` = Media/Radio, `2` = Navigation/CarPlay/Android Auto. Adjusts front-panel knob focus. |
| **`0x84`** | `0x08008809` | `[routeId]` | **Audio Multiplexer Route**: Controls hardware audio switch (`AT+AUDROUTE`): `0` = SoC DAC direct, `3` = Factory AUX / MCU passthrough. |
| **`0x85`** | `0x08008BA9` | `[data...]` | **App Protocol Response**: Acknowledges inbound telemetry frames. |
| **`0x87`** | `0x080087A1` | `[4 bytes]` | **Bluetooth AT / Menu Command Relay**: Relays AT commands (`AT+...`) to the onboard Bluetooth module. |
| **`0x88`** | `0x0800893D` | `[8 bytes]` | **TEA Cryptographic Handshake**: Deciphers an 8-byte token using 32 rounds of TEA block cipher (`0x080050A0`) against a fixed 128-bit key for vendor authentication. *(Note: Not a real-time clock setter).* |
| **`0xA0`** | `0x080089D9` | `[settingId, value]` | **UI Settings Sync Channel**: Jump table dispatched via `TBB [PC, R0]` at `0x080089E2`. See detailed table below. |
| **`0xE1`** | `0x080088E1` | `[0x00, 0x00]` | **Reboot to Bootloader**: Writes magic `0x5555AAAA` to SRAM `0x20004004` and spins for watchdog reset to enter firmware update mode. |
| **`0xFF`** | `0x080088E9` | `[0x00]` | **System State Reset**: Soft-resets peripheral state machines and clears CAN buffers. |

### `CMD 0xA0` — UI Settings Jump Table (Disassembled from `0x080089D8`)

When `CMD 0xA0` is received, the MCU reads `settingId` (`payload[0]`) and indexes a `TBB` jump table to update the global configuration struct at SRAM `0x200001D8`.

| Setting ID (Hex) | Setting ID (Dec) | Handler Address | Config Struct Offset | Permitted Values | Function & Hardware Impact |
|:---:|:---:|:---:|:---:|:---:|---|
| **`0x00`** | `0` | `0x080089F8` | `[config + 0x3B]` | `0`=Normal, `1`=Day, `2`=Night/Dim, `3`=Custom | Sets display mode profile and calls `0x08007600(0x0C)` for screen brightness curve. |
| **`0x01`..`0x06`** | `1`..`6` | `0x08008B88` | — | — | **No-op**: Bypasses processing, returns immediately. |
| **`0x07`** | `7` | `0x08008A40` | `[config + 0x3A]` | `0` = Off, `1` = On | **Dynamic Parking Guidelines**: Enables/disables steering-angle trajectory calculation from CAN (`0x3C4`). |
| **`0x08`** | `8` | `0x08008A5A` | `[config + 0x39]` | `0` = Off, `1` = On | **Reverse Warning Buzzer**: Toggles internal MCU piezo buzzer during parking sensor alerts. |
| **`0x09`** | `9` | `0x08008A74` | `[config + 0x38]` | `0` = Aftermarket 3.5mm, `1` = Factory OEM Roof Mic | **Microphone Input Source / Audio Mux Switch**: Flips `GPIOB Pin 6` (`0x08005AA0`) between the external 3.5mm jack (`0`) and the 28-pin Toyota factory harness roof mic (`1`). |
| **`0x0A`** | `10` | `0x08008A9E` | `[config + 0x3C]` | `0` to `9` (0% to 90%) | **Reversing Volume Ducking**: Attenuates audio volume level when reverse gear is engaged. |
| **`0x0B`** | `11` | `0x08008AB2` | `[config + 0x3D/3E]` | `0` = Off, `1` = On | **PDC Radar Overlay**: Enables/disables parking distance sensor graphics. |
| **`0x0C`** | `12` | `0x08008B02` | `[config + 0x40]` | `0` to `60` | **PDC Radar Timeout / Range**: Configures radar display distance threshold. |
| **`0x0D`** | `13` | `0x08008B2A` | `[config + 0x42]` | `0` = Off, `1` = On | **Front Camera / 360 Panorama**: Enables front-camera auto-switch on exiting reverse gear. |
| **`0x0E`** | `14` | `0x08008B88` | — | — | **No-op**: Bypasses processing. |
| **`0x0F`** | `15` | `0x08008B46` | `[config + 0x43]` | `0` to `100` (%) | **Display Brightness**: Sets LCD backlight PWM duty cycle. |
| **`0x10`** | `16` | `0x08008B52` | `[config + 0x44]` | `0` to `100` (%) | **Display Contrast**: Adjusts LCD contrast register. |
| **`0x11`** | `17` | `0x08008B5E` | `[config + 0x45]` | `0` = Aftermarket, `1` = Factory OEM | **Camera Type / Video Relay Multiplexer**: `0` keeps factory relay off and routes video mux to ArkMicro SoC; `1` asserts GPIOC Pin 13 relay for Toyota OEM camera bypass. |

## 6. How to Modify CAN Codes & Build Updates

Using the provided toolset in `tools/mcu_builder/`:

1. **Modify CAN IDs in Table**:
   - Standard Toyota Prado 150 SWC broadcast is `0x3C4`.
   - Update Mode 1 Entry 7 from `0x105` to `0x3C4` using `mcu_rebuild.py` or `can_config_template.json`.
2. **Rebuild the Firmware & Package**:
   ```bash
   ./tools/mcu_builder/build_mcu_update.sh --preset toyota_prado_150
   ```
   **⚠️ This preset also silently patches a second CAN ID** (Mode 1 Entry 4,
   `0x185 -> 0x025`, the reverse/parking-sensor handler) that is **not**
   verified against a real vehicle capture — see the warning at the top of
   this document before running this. The build script prints the same
   warning when this preset is selected.
3. **Deploy via USB**:
   - Copy `output/usb_root/auto_upgrade.txt` and `output/usb_root/can_app.bin` to the root of a FAT32 USB drive.
   - Plug into the unit to auto-flash.
   - **Keep a copy of the stock `can_app.bin` first** — no image-level
     checksum/CRC verification is confirmed to exist, so there is no
     known-good fallback if a patched image causes problems other than
     re-flashing the original.

## 8. Bluetooth Module Subsystem (`USART3` @ `0x08006700`)

The STM32 MCU controls the onboard **Feasycom FSC-BT8251** Bluetooth 5.0 module via dedicated hardware `USART3`:

* **Module Power**: Gated by **`GPIOA Pin 2`** (`0x080059E8`).
* **Hardcoded AT Initialization Sequence**:
  * `AT+LINKCFG=0\r\n`: Disables automatic legacy reconnection on power-up.
  * `AT+NAME=DC_AUDIO_BT5.0,1\r\n`: Sets default device broadcast name.
  * `AT+PIN=0000\r\n`: Sets default pairing PIN code.
  * `AT+LEDCFG=3\r\n`: Configures Bluetooth status LED blinking rate.
  * `AT+AUDROUTE=1\r\n` / `AT+AUDROUTE=2\r\n`: Switches audio paths between hands-free telephony (HFP) and media streaming (A2DP).
  * `AT+UPGRADE\r\n`: Triggers Bluetooth module UART bootloader flashing mode.
* **SoC Command Passthrough**:
  * Inbound `CMD 0x87` from `/dev/ttyHS0` is piped directly to `USART3` to execute custom AT commands.
  * Outbound responses from `USART3` are framed as `CMD 0x07` packets and transmitted to the SoC.

## 9. Cryptographic Watchdog & Anti-Clone Authentication (`CMD 0x88` @ `0x080050A0`)

The MCU firmware implements a hardware-software challenge-response authentication handshake using the **32-Round Tiny Encryption Algorithm (TEA)**:

* **Encryption Routine**: Located at `0x080050A0` with standard TEA constant `DELTA = 0x9E3779B9`.
* **Decryption Routine**: Located at `0x08005124`.
* **Operation**:
  1. The SoC sends an 8-byte challenge packet via `CMD 0x88`:
     $$\text{Packet: }\texttt{[0x2E] [0x88] [0x08] [d0..d7] [CHK]}$$
  2. The MCU decrypts the 64-bit block into two 32-bit words `v0` and `v1`, re-encrypts the block using the 128-bit key stored at `0x20000098`, and verifies the token.
  3. **Watchdog Action**: If the SoC fails to complete the challenge within the periodic timer window, the MCU enters a restricted security mode (disabling the touchscreen pass-through switch on `GPIOB Pin 0` and muting audio via `GPIOA Pin 1`).

### **Hardware I2C2 Audio Processor Engine (`0x40005800` on `PB10`/`PB11`)**

Unlike the Volvo reference binary which lacked STM32 I2C references, `live_app_1302.bin` includes the dedicated **hardware `I2C2` driver (`0x40005800`)**:

| MCU Pin | Peripheral Function | Destination on PCB |
|---|---|---|
| **`GPIOB Pin 10`** | `I2C2_SCL` | BD37033 Pin 28 (`SCL`) |
| **`GPIOB Pin 11`** | `I2C2_SDA` | BD37033 Pin 27 (`SDA`) |
| **`GPIOA Pin 7`** | Audio Subsystem Power Gate | $+8.5\text{V}$ Analog Power Switch |
| **`GPIOA Pin 1`** | Power Amplifier Mute | TDA7388 `MUTE` Pin |

The MCU firmware dispatches volume, 3-band EQ, and fader settings (`0x0800B416`..`0x0800B490`) directly to the BD37033 at I2C address `0x40` upon receiving `CMD 0xA0` frames from the Linux host.
